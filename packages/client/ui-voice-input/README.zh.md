# @deepseek-ai/dsh-client-ui-voice-input

[English](README.md) | 中文

语音输入插件（浏览器侧）：composer 的具名 `conversation.input.voice` seat——位于模型选择与发送按钮之间的纯图标麦克风按钮（无轮廓、无背景）。点击即启动浏览器的 SpeechRecognition（在 Windows/Edge 上即操作系统语音平台），再次点击停止；录制期间最终片段会以单空格连接并持续写入 composer 草稿，用户可在发送前审阅。浏览器未暴露识别器时按钮不渲染。

识别器出错时恢复录制前草稿，并通过按钮标签提示；`aborted` 是用户主动停止，保持静默。composer 处于锁定或输入机繁忙（adjudicating/submitting）时该 seat 禁用；录制期间锁定会中止识别器。按钮从不抢占输入框焦点。

该贡献只依赖会话标准工具包（`useInput` / `inputActions`）与浏览器 API：不发起 Host 请求、不产生 Session 事件、不生成投影——转写文本与键入文本完全相同。

`/client` 导出面为插件本体（`apply`/`inject`）。

## 模型体验

间接影响：转写文本与键入文本一样落入 composer 草稿，因此模型只会在用户发送时看到它。该功能本身不添加提示词内容，录制期间也不会发送任何内容。

识别语言跟随 `navigator.language`（浏览器/系统默认——Windows 转写跟随系统语言），启用连续聆听与中间结果，最终片段渐进提交。

#### KV Cache 影响

无——除用户发送的草稿外不产生任何提示词内容。

## 已知限制与暂缓事项

- **引擎依赖浏览器**——Web Speech API 由浏览器实现（Windows/Edge 使用操作系统语音平台；Chrome 桌面版使用自己的服务），因此识别质量、语言覆盖与网络要求都跟随浏览器，而非本包。没有打包的离线引擎，也没有自定义模型或语言选择器。
- **录制期间草稿尾部归录制所有**——录制时每次结果事件都会将草稿重写为基础草稿加累积转写；录制期间键入的内容会被下一条结果覆盖。请在停止后键入。
- **不自动发送、不支持按住说话**——按钮是开关；转写从不自行提交，引擎在用户停止前会持续聆听。
