# Agent Note: 将助手推理保留在工具组内

Status: implemented

[English](2026-09-05-think-tool-group-placement.md) | 中文

## Problem

混合助手步骤包含推理和回答内容。根据可见文本对整个步骤分组，会在首个回答 token 到达时将其 Think 披露行移到前面的工具组之外。可变节点存储在增量更新期间也保留对象标识，因此只读取存储而不选择位置变化，可能使最初为空的流式步骤一直留在组外。

## Decision

聊天视图通过订阅单个节点的推理组件，将未中断的推理渲染在相邻工作序列内。混合步骤通过现有助手 slot 渲染文本和图片，并省略推理。推理组件在首个回答 token 到达时保留自身标识，且拥有独立的滚动锚点。被中断的步骤仍在普通消息流中显示停止标记。

父组件通过框架会话 hook 选择推理位置和序列活动状态的原始值。仅文本增量不会改变该选择；每个节点组件观察自己的内容。手动折叠仍由现有工具组负责。

## Alternatives considered

**将整个步骤移入组内。** 这会使回答文本和附件随工具活动一起隐藏。

**每次节点增量都重建消息流。** 即使位置和活动状态不变，这也会在流式输出期间增加整个列表的工作量。

## Consequences

Think 披露行与工具活动保持在一起，回答内容则可以独立阅读。组件回归用例覆盖空内容到推理的流式变化、混合输出、披露行标识、手动折叠和已完成内容的冷启动渲染。Web 回归用例通过真实组合重放录制的 question-composer 对话，并为组内两条推理摘要生成快照。会话事件和模型请求均不改变。
