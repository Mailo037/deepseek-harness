# Agent Note: JSONL 陈旧 end-seed 冲突恢复

Status: implemented

[English](2026-08-24-jsonl-stale-end-seed-collision-recovery.md) | 中文

## 问题

JSONL 只在单个后端实例内协调写入。带 seed 的恢复会在已存储长度处追加纯日志 `session/end-seed` 事件，而仍在另一进程中拥有同一 Session 的所有者可以在该 seq 追加用户可见的生命周期事件。两个各自连续的 writer 会由此留下一个相邻重复项：标记在前，活动生命周期在后。严格扫描会拒绝后续已提交轮次，因此一个技术标记会使整个对话不可用，即使移除它即可恢复唯一连续的事件流。

该模式比一般并发写入损坏更狭窄。冲突中的第一个事件始终为 `session/end-seed`，不包含模型或表层内容；下一个事件精确重复其 seq；每个保留事件仍满足 `events[i].seq === i`。对于其他重复或缺口，没有证据可以证明哪个 writer 分支权威。

## 决策

`SessionLogScanner` 只将一种物理模式视为可恢复：当 seq 冲突紧前的事件是 `session/end-seed`，且候选事件重复该标记的 seq 时，扫描器移除该标记，并在当前长度接受候选事件。活动生命周期及全部后续事件保留其记录的 seq 与 time。原始日志和 Zstandard 日志共享同一扫描器，因此该规则适用于两种编码。

所有其他 seq 不匹配保留现有损坏行为。扫描器尤其不会重新编号事件、在两个包含内容的事件之间选边、向后搜索标记，也不会容忍恢复后的缺口。

已存储产物保持仅追加。恢复是一项逻辑读取规则，而非自动重写，因此打开历史不会修改或替换用户数据。后续 append 从恢复后的逻辑事件数量继续。

## 考虑过的替代方案

**拒绝所有已提交重复项。** 这保留最简单的存储不变量，却会因为一个只用于生命周期分类的标记而使原本连续的对话不可用，也丢弃了相邻活动生命周期给出的更强证据。

**重新编号活动 writer 的后缀。** 这会改变持久事件身份、`sourceEventSeqs`，以及任何以 `(session id, seq)` 为键的外部关联；当唯一冲突事件是不含内容的标记时，也无法证明重写压缩历史具有正当性。

**接受任意重复 seq。** 两个包含内容的分支没有安全的自动胜者。宽泛容忍会把可检测损坏变成静默历史丢失，因此例外必须绑定唯一纯日志标记及其紧邻关系。

**在同一变更中增加跨进程 writer 租约。** 租约可以防止未来冲突，却不能使现有日志可读；崩溃安全的所有权需要独立设计生命周期、陈旧所有者处理和多平台行为。JSONL 继续声明每会话一个活动 writer；本决策只恢复已证实的标记冲突，不声称多进程安全。

## 验证

扫描器覆盖会提交一个完整轮次、一个陈旧 end-seed 标记，以及从相同 seq 开始的第二个完整生命周期。测试要求标记消失、生命周期保持连续，并且已提交字节游标到达产物末尾。负向控制会将该标记替换为普通重复项，并要求保留现有的已提交区域损坏错误。

## 后果

携带这一精确冲突的对话可以在不重新编号数据或重写存储的情况下加载。原始导出仍会暴露物理标记，因为它承诺提供精确产物字节，而逻辑历史会忽略该标记。一般并发 JSONL writer 仍不受支持，所有有歧义的不匹配仍会快速失败。
