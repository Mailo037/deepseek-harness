# Agent Note: Web 辅助工具的构建前置条件

Status: implemented

[English](2026-09-05-web-helper-build-prerequisites.md) | 中文

## 问题

从源码运行的 Web 主机会导入生成的 Typert 贡献模块，并提供客户端插件 bundle。前端构建也会从 `lib/` 导入工作区库。只构建前端会在尚未构建的仓库中失败，并可能在源码修改后提供陈旧的插件。

## 决策

[开发辅助工具](../../../../scripts/dsh-dev.mjs) 在启动 Web 主机前运行仓库的完整 `build`。该构建负责主机生成、客户端编译与打包、前端编译以及客户端构建记录。构建失败会阻止启动。`--full` 仍可使用，并选择相同的构建。直接运行 `pnpm dsh web` 仍需要预先准备产物。

## 考虑过的替代方案

**仅在指定文件缺失时构建。** 文件存在不能证明动态加载的插件完整或最新。复用完整构建可避免在辅助工具中维护第二份依赖清单。

**要求手动构建或传入 `--full`。** 这会使默认的构建并启动命令无法自行准备前置产物。

## 后果

每次调用辅助工具都会花时间构建 harness。已有产物的用户可以直接启动主机。子进程回归测试覆盖默认启动、显式 `--full` 启动、主机参数转发，以及构建失败后停止。此修改仅影响仓库工具；模型请求、协议输出和应用转录均保持不变。
