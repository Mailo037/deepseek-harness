# Agent Note: AI-assisted Harness update review

Status: implemented

[English](2026-08-22-ai-assisted-harness-update-review.md) | 中文

## Problem

已安装的非官方 Harness 可能同时包含三组独立演进的改动：DeepSeek 官方上游、非官方发行版维护的改动，以及用户自己的本地定制。既有的「关于」更新器只会把当前分支快进到其已配置的 Git 上游。它无法判断如何在保留本地行为的前提下集成来源改动，而盲目合并或重置可能丢失用户定制。

## Decision

「关于」分区持有一张独立的 **AI 辅助更新**卡片，并使用共享的定制 `SurfaceCard`、`LabeledField`、`ComparisonRail` 和 `Select` 原子组件。用户可选择维护中的非官方发行版或 DeepSeek 官方上游；默认选择非官方发行版，因为它包含本产品持续维护的适配。卡片解析所选 Harness 工作区，在其中准备一个普通空白会话，加载该会话由宿主报告的模型目录，并让用户选择审查模型。启动审查会发送一条持久化用户提示并打开该会话，因此所有分析、提问、批准、工具调用和结果都在普通会话中可见。

提示会指定所选仓库，并要求模型自行发现其当前默认分支和最新发布标签。提示要求报告本地与来源版本、merge base、ahead/behind 数量，并建立包含来源改动、发行版维护改动和本地用户定制的三部分清单。每项来源改动都必须分类为直接集成、围绕定制作适配或有意不采纳。分析期间可以抓取带命名空间的远程 ref；修改受跟踪文件前必须获得明确批准。获准的改动使用隔离的 `harness-sync/*` 分支和 worktree，绝不使用活动工作树。Push、merge、发布、部署、重启、reset、rebase 和清理活动工作树仍不在审查权限内。

普通应用更新器仍是免额度的默认路径，并可继续从已配置的 Git 上游快进和重启。AI 路径完全可选：加载宿主模型目录不会发起模型请求，只有用户明确启动可见的更新会话后才可能消耗额度。

## Alternatives considered

**让既有自更新服务合并任一仓库。** 拒绝，因为自更新拥有狭窄的快进和重启契约。分歧历史的集成需要架构判断、冲突审查和用户批准，而不是更强的 Git 修改原语。

**运行隐藏的后台模型调用并自动应用其补丁。** 拒绝，因为隐藏工作会移除普通会话日志、批准控制、模型选择器、进度 UI 和后续对话，而高风险集成恰恰需要这些能力。

**硬编码能力最强的模型。** 拒绝，因为不同部署公开不同的提供商与目录，且仓库禁止没有依据的部署可调项。准备好的会话报告可选项；用户从中选择，初始选中该会话当前使用的模型。

## Consequences

该功能复用既有工作区、会话、模型目录、提示和导航行为，不会新增第二套 Agent runtime 或 Git 线上 API。设置页内不会显示实时来源版本数据；启动后的 AI 会话统一持有新鲜度、证据和解释。准备模型列表可能会创建或复用一个空白会话，但在用户选择**开始 AI 更新**前不会发起模型请求。可复用的定制卡片、字段和对比原子组件也可直接供其他客户端包使用。

## Testing

控制器规格固定两种来源及其默认值、工作区准备、宿主报告的选项、未列出但可路由的当前模型、提示提交前的模型选择、失败恢复、导航，以及持久化提示中的定制保留与安全条款。「关于」组件覆盖固定可选额度文案，以及从加载模型到打开可见审查会话的完整定制控件。原子组件覆盖固定卡片标签、自定义控件标签和装饰性对比语义。包 apply 套件固定新增的会话与工作区服务注入。一项无密钥 Web replay 快照固定组装后的「关于」卡片、默认来源、定制来源选择器、明确的额度边界，以及不加载或启动模型时的来源切换。
