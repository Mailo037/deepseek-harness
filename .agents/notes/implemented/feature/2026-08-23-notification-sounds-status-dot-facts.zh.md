# Agent Note: 通知音效与会话状态圆点数据耦合

Status: implemented

[English](2026-08-23-notification-sounds-status-dot-facts.md) | 中文

## 问题

后台会话完成（或失败）此前只能通过侧边栏圆点颜色变化察觉。窗口失焦的用户没有任何信号表明任务已完成、交互开始阻塞，或一轮以终端失败结束。

## 决策

新增客户端插件包 `ui-notifications`：持有 Host 持久化的选择性偏好（`enabled`，默认 false）以及每个事件类型的内置音效（`doneSound`/`attentionSound`/`errorSound`，各有四个合成音效可选）。设置行注册进 `settings.general.item`；总开关控制三行按事件选择的音效选择器并带试听按钮。

监听器订阅会话列表快照存储——正是 `SessionSummary` 投影为工作区浏览器状态圆点的同一权威来源——并相对上一次观察的快照派生转换：行的 `attention` 首次出现触发 `error`，`pendingInteraction` 首次出现触发 `attention`，运行停止（或空闲行上首个后台任务完成且无其他待处理事项）触发 `done`。一次刷新至多播放一个音效，优先级 error > attention > done。基线静默建立，因此启动与重连重拉从不重放已有状态；subagent 来源的行保持静音，因为其生命周期通过父会话的后台活动呈现。

音效用 Web Audio 振荡器 + 增益包络合成，打包产物不含音频资源；缺失或挂起的 `AudioContext` 退化为静默而非抛错。

## 已考虑的替代方案

**在 ui-workspace 的树派生中派生事件。** 否决：该派生是渲染作用域的（折叠分组跳过行投影），恰恰在后台会话最需要通知时会漏掉它们，而且声音输出不是展示状态。

**浏览器桌面通知。** 暂缓：需要权限流程和各操作系统的适配；声音已覆盖"窗口开着但失焦"的场景。已记录在包 README 的已知限制下。

## 后果

用户选择加入后，完成、阻塞交互与失败现在会有声音提示。事件词汇与圆点状态一一对应，未来新增圆点状态有明确的位置添加对应音效。包测试固定了转换规则、刷新优先级、基线建立、经设置作用域的写入路由，以及合成音色的声部数量。
