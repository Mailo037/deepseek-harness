# Agent Note: Mobile sidebar drawer and settings sheet at phone viewports

Status: implemented

[English](2026-08-21-mobile-sidebar-drawer-and-settings-sheet.md) | 中文

## Problem

在自动折叠断点（1024px）以下，侧边栏折叠为 56px 轨道，手动重新展开时会在内联位置按拖动宽度渲染展开栏，把会话栏挤压到中栏剩余的空间。在手机尺寸的 viewport 上，这会令会话不可用：390px 屏幕配 280px 侧边栏时，会话只剩约 110px。设置模态框在任何视口宽度下都保持固定的两栏布局——188px 导航栏加内容栏——因此在手机上内容栏会缩到约 160px，偏好行被压扁。

## Decision

布局框架在新增的 `SIDEBAR_DRAWER_BREAKPOINT`（640px）以下把重新展开的侧边栏渲染为覆盖式抽屉，而不是挤压中栏。抽屉打开期间网格保持侧边栏轨道为零（与关闭时脱离 grid 的轨道一致），因此中栏不会被推向右侧并保持全宽；侧边栏栏成为绝对定位层，宽度为抽屉宽度（`drawerWidth()`：上限 320px，始终留出 48px 视口边距），其后是遮罩 token。点击遮罩通过既有的窄屏切换语义关闭抽屉；抽屉栏在 150ms 宽内容淡出期间保持覆盖模式，以免收起的交叉淡化被重排裁剪。打开抽屉时栏从左侧滑入（300ms translateX 加透明度，使用主题慢速缓动）。在抽屉断点与自动折叠断点之间，重新展开仍会挤压中栏，保留既有行为及其测试。关闭的侧边栏后来在该断点以下彻底去掉了轨道（见[会话页头更多选项与移动端外壳](2026-08-21-chat-header-options-and-mobile-shell.zh.md)）：其列轨道整体退出 grid，由框架的角落按钮打开抽屉。

设置面板在 640px 以下改为堆叠布局：变成全屏面板（`100vw` × `100dvh`，无圆角），导航栏成为内容上方的一整行，分区单元格横向滚动而标题保持固定。

## Alternatives considered

**在自动折叠断点以下的每个宽度都使用覆盖式抽屉。** 拒绝：640px 与 1024px 之间的挤压式重新展开是既有且经过测试的契约（chat-scroll、composer 几何），平板与窄桌面窗口可容纳 280px 侧边栏；抽屉只为无法容纳的手机场景而存在。

**限制展开侧边栏宽度，让中栏保有最小值。** 拒绝：在 390px viewport 上，任何内联展开的侧边栏仍会让会话只剩一条窄缝；只有覆盖才能让中栏保持全宽。

**全宽抽屉。** 拒绝：用户抱怨的是侧边栏占满整个屏幕；保留可见遮罩余量并采用标准点击关闭遮罩的部分覆盖才是对症的修正。

## Consequences

手机 viewport 在侧边栏打开时仍保有全宽会话——零网格轨道意味着抽屉打开时中栏不会位移——设置对话框把整张面板交给各偏好行。抽屉以 300ms 从左滑入打开；收起复用既有轨道几何与交叉淡化，因此侧边栏外壳及其 slot 不变；呈现方式的切换由布局框架持有。640px–1024px 的挤压契约未被触碰，既有的窄屏 e2e 场景仍然有效。抽屉遮罩是指针专用可供性（与设置遮罩一致）；键盘用户通过抽屉栏内部的切换按钮关闭，而——自关闭轨道离开框架后——通过框架的角落按钮打开。

## Testing

AppFrame 规格覆盖抽屉：390px 下的覆盖而不挤压中栏、低于边距下限时的宽度钳制、经淡化过程的遮罩点击关闭、收起时 150ms 的覆盖保持，以及 640px–1023px 的挤压回退。columns 规格覆盖 `drawerWidth`。两个 web e2e 场景固定组装后的行为：手机 viewport 抽屉往返（中栏宽度不变、遮罩关闭）与手机 viewport 设置面板（面板占满 viewport、导航堆叠在内容上方）。完整 `pnpm run test:gui` 套件通过。
