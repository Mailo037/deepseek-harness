# Agent Note: GoalBar 触控布局下点击条带即可展开/收起

Status: implemented

[English](2026-08-26-goal-bar-tap-to-toggle.md) | 中文

## 问题

在触控布局中，GoalBar 的展开/收起操作需通过 kebab 菜单进入：条带内的图标行被隐藏，所有阅读操作（包括展开/收起）都折叠在菜单中。阅读完整目标是非变更操作中最频繁的，要求一次菜单点击才能看到完整内容，使披露变得不够直接。产品需求 (2026-08-26) 要求点击条带主体即可切换阅读视图。

## 决策

条带主体（`css.bar`，收起和展开两种状态）上添加 `onClick={handleBarTap}`。处理器忽略目标为控件（`closest('button')`：kebab 座及将来可能的按钮）的点击，仅在触控布局媒体查询匹配时切换 `expanded` 状态。查询字符串 `'(max-width: 768px), (hover: none), (pointer: coarse)'` 与 `GoalBar.module.css` 的触控布局块保持一致，使 JS 门控和 CSS 布局始终同步；调用使用可选链，确保 jsdom 和非浏览器环境无操作。触控布局块还设置了 `cursor: pointer` 属性，在窄桌面窗口（该查询在非触控指针下也匹配）中有实际意义。

精细指针桌面端被刻意排除：展开视图中的目标文本可选中，点击条带会破坏选中操作。这些布局保持悬停显示 chevron 作为唯一切换方式。kebab 菜单中保留展开/收起项，以确保屏幕阅读器和键盘用户在触控布局中仍有可访问的入口。

## 考虑的替代方案

**在所有布局上启用切换。** 一个处理器，无媒体查询。已否决，因为精细指针桌面端上展开的目标文本可选中；意图选中文本的点击会收起面板。chevron 已覆盖桌面端的披露需求。

**仅靠 CSS 配合 chevron 作为唯一触发方式。** 不增加新行为；触控路径仍只有菜单入口。已否决，因为这正是需求所指出的问题。

**将展开项移出 kebab 菜单。** 在收起条带内增加第二个始终可见的图标。已否决，这引入了菜单折叠原本要避免的宽度压力，而点击条带已覆盖常见场景，无需新增界面元素。

## 后果

- 触控布局下点击条带主体切换阅读视图；点击 kebab 座、菜单列表（已阻止冒泡）和菜单项保持各自的操作。
- 桌面端行为不变：chevron 仍是唯一切换方式，展开视图中的目标文本可自由选中。
- 媒体查询在两处（CSS 块和 JS 常量）均有声明，两者须同步修改。常量注释说明了该耦合关系。
- 组件测试覆盖了门控逻辑：触控点击可切换，kebab 点击不触发切换，精细指针桌面端点击条带主体无操作。
