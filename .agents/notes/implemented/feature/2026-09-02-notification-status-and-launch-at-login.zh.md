# Agent Note: 浏览器通知状态展示与开机自启偏好

Status: implemented

[English](2026-09-02-notification-status-and-launch-at-login.md) | 中文

## 问题

通知音效行此前只显示功能自身的开/关开关。系统通知能否真正出现，取决于用户在浏览器（应用之外）控制的浏览器权限：开启了功能的用户无法看到浏览器已阻止通知，而「从未询问」的浏览器与已授权的浏览器在界面上毫无区别。此外，桌面用户没有任何办法让应用在电脑启动时自动运行。

## 决策

**浏览器通知。** `ui-notifications` 运行时通过可注入的 face 读取浏览器的 `Notification.permission`，并在每个快照中以 `permission`（`granted`／`default`／`denied`／`unsupported`）发布。设置行显示一条带状态圆点的实时状态栏：状态为 `default` 时提供显式的「申请权限」入口，被阻止时给出指向浏览器站点设置的提示——开关本身仍是功能开关，打开时会顺带触发权限申请。由于 Notification API 没有权限变化事件，客户端在文档可见性变化与窗口聚焦时重新读取状态，因此在浏览器站点设置中做出的授权无需刷新页面即可到达已打开的页面。

**开机自启。** 新的 `ui-launch` 客户端包持有持久的 `ui-launch` 设置命名空间（`launchAtLogin`）以及 General 设置中的一行。后端接缝归运行环境所有：Host 侧的 `ctx.inject(['settings', 'launchSettings'])` 等待运行环境的后端，只在后端存在时注册命名空间，并把提交的值应用过去。现有两个后端：Electron 主进程通过 `app.setLoginItemSettings` 提供登录项后端（Windows 始终支持；仅限已打包的 macOS；Linux 报告不支持），web 组合包的 `web-launch-item` 行提供一个 Windows 每用户注册表 Run 键后端（`HKCU\...\Run`，值名 `DeepSeekHarness`），其命令从提供时采样的安装根目录重启 `pnpm dsh --profile web --no-open`——macOS 或 Linux 的 web 宿主不提供任何后端，行在那里不渲染。没有组合后端时命名空间保持未注册，绝不会出现一个无法生效的开关。只有已存储用户覆盖时才在启动时执行应用，因此未被触碰的开关不会覆盖操作系统里已有的登录项；提交的变更总是应用，这也会在应用更新后修复过期的登录项路径，而注销会先查询值再删除，因此条目本就不存在属于「已满足」而非错误。`bootWebHost` 保持不含 Electron：Electron 后端经由 Electron 入口提供的启动选项传入，普通 Node 冒烟路径因此保持可加载。

## 已考虑的替代方案

**把权限状态直接投射为该行的开关状态。** 否决：功能开关（音效是否播放）与浏览器能力（系统通知是否可能出现）是用户在不同地方控制的不同决策；合并二者会让开关至少对其一失实。

**通过 API 网关提供启动设置。** 否决：该偏好与其他任何用户设置一样是持久的用户设置，设置传输层已经负责持久化与转发，而操作系统层面的应用属于运行环境策略——网关方法会把 Electron 特有的语义塞进共享的线上契约。

**把操作系统的登录项状态回读到界面。** 暂缓：Electron 暴露了 `getLoginItemSettings`，但系统策略可能在应用之外改动条目；诚实地建模该状态需要一个尚不存在的事件源。开关反映的是持久化偏好，后端在下一次变更或应用启动时重新写回。

## 后果

快照新增了必填的 `permission` 字段，该行注入的 face 新增了 `requestPermission`；二者都是增量变更。`ui-launch` 命名空间只在组合了后端的部署里出现在设置文档中，其 user 节记录用户的开关值。应用开关会写入操作系统的启动状态——Windows web 后端写入每用户注册表 Run 键，Electron 后端写入登录项——而 Host 设置文档仍然是唯一的偏好权威。

## 测试

运行时覆盖钉住权限投射、按需刷新再发布、仅从 `default` 发起申请以及失败遏制；行覆盖按状态钉住状态文案、提示与申请入口。Host 覆盖钉住启动时应用已存储覆盖、绝不应用的选择性默认值，以及没有后端时的命名空间缺位；Electron 覆盖钉住平台门控（Windows、Linux、未打包 macOS）与不含 Electron 的宿主接线；web 后端覆盖钉住注册表命令形态、先查询后删除的注销幂等性，以及仅 Windows 提供的行为。真实组合的宿主冒烟测试会启动包含启动后端行的完整 web profile。浏览器 golden 在所有主机上钉住行的「不渲染」状态——e2e scaffold 会禁用 `web-launch-item`，使 Windows 与 Linux 的组合完全一致——而行自身的可见性由组件测试钉住。
