# Agent Note: 引导式首次运行恢复

Status: implemented

[English](2026-08-22-guided-onboarding-recovery.md) | 中文

## 问题

首次运行的 Models 步骤会把缺少适配器、路由不活跃、联接失败或凭据路径只读视为静默完成的理由。新用户随后回到仍无法发出有用请求的输入框，却没有说明或下一步操作。独立的 Workspace 选择器已经持有目录选择和路径接纳，但引导没有办法把用户送往这项既有交互。

## 决策

`ui-settings-models` 继续持有有序的首次运行步骤。它会为每一种无法服务请求的 Models 就绪状态渲染可恢复弹窗，说明相应条件，并通过引导 owner 回调打开既有的 Models 分区。缺少密钥的表单保留只写的 `credentials.set` 路径，同时也提供该 Models 操作。**稍后配置**只完成当前协调器步骤；它不会报告提供方已经配置完成。

提供方可用后，同一个步骤会展示紧凑的三段旅程：提供方、工作区、再到第一个任务。缺少 Workspace 时提供**选择工作区**。该操作调用可选的 `workspacePickerRequests` 服务，而不会创建选择器、选择后端或接纳路径。`ui-workspace` 在已挂载的主视觉 `WorkspacePicker` 中接收递增请求，并拉起与侧栏**添加工作区**操作相同的目录流 slot；组合出的 native 或 browse occupant 独自选择实现。这个外部请求会绕过普通输入框的 Workspace 菜单；后者的**选择工作区**控制即使在没有 Workspace 时仍会打开菜单，其中包含独立会话目标与**添加工作区…**操作。Workspace 步骤会在外部选择器后方保持挂载和可见，并在请求持有交互期间禁用两个操作。取消会原位恢复操作，完成选择则让同一个引导界面进入最终交接。该步骤与最后交接都提供**暂时跳过**：它只完成当前协调器轮次，不会选择 Workspace、创建 Session，也不会记录成功配置。

这只是浏览器展示行为。没有新的面向模型数据进入 agent loop，因此不引入会话事件。

## 曾考虑的替代方案

**继续静默完成不可用状态。** 不采用：它会让首次运行用户既没有可用路由，也没有诊断路径。

**让引导拥有自己的目录选择器。** 不采用：这会重复 `ui-workspace` 已经持有的目录流选择、后端选择、取消和 Host 路径接纳。

**把稍后配置当作提供方已就绪。** 不采用：推迟不是成功配置，不能压制后续恢复。

**强制完成 Workspace 或第一个任务。** 不采用：用户可能需要推迟设置，同时保留常规选择器与输入框供稍后使用。

## 后果

每一种缺失或不可用的模型路径都有可操作的 Models 恢复入口。已经有提供方的用户会进入既有 Workspace 选择器，之后收到简洁的首个任务交接，或者明确推迟任一步而不产生 Workspace 或 Session。未挂载 `ui-workspace` 的组合中，可选 picker 请求没有作用；引导会保持工作区弹窗打开并说明选择不可用，而不是错误地完成。

聚焦的 Models 和 WorkspacePicker 组件覆盖固定恢复操作、明确的推迟、提供方到工作区再到任务的推进，以及请求信号。组装后的浏览器首次运行场景会快照欢迎、缺少密钥与工作区弹窗，调用**打开模型设置**，并确认**暂时跳过**会让常规选择器保持可用。
