# Agent Note: 交互式 Harness home 重置

状态：已实现

[English](2026-09-01-interactive-harness-reset.md) | 中文

## 问题

清除持久化对话需要手动查找并删除 `$DSH_HOME` 下由实现管理的目录。即使用户只想清空聊天列表，删除整个目录也会一并丢失模型选择、托管 API 凭据、profile overlay 和用户 skill。产品命令需要在删除前说明范围、要求显式确认，并拒绝宽泛的文件系统位置。

## 决策

产品启动器提供交互式 `dsh reset` 模式，并以 `pnpm dsh:reset` 作为源码 checkout 别名。它解析与其他启动模式相同的 `$DSH_HOME`，并提供两种删除范围：

- 聊天数据会移除 `sessions`、`attachments` 和 `storages` 子目录。这些位置共同保存 session 日志、附件字节、workspace 聊天列表、归档与置顶状态以及消息反馈。该命令保留 `settings.yaml`、`.credentials.yaml`、profile、skill、提供方/模型设置与 API 凭据。
- 完整重置会移除解析后的 `$DSH_HOME` 目录及其下全部用户状态。

选择范围并不授权删除。启动器显示解析后的路径与所选范围的后果后，会要求一次明确的 `y/N` 确认。空输入、否定输入或取消均不改变文件系统。聊天范围使用固定的子目录名称；完整重置拒绝文件系统根目录、操作系统用户 home 和当前工作目录。执行命令时必须停止 Harness 应用，避免进程在删除期间持有或重新写入文件。

## 考虑过的替代方案

**只删除 `sessions`。** 不采用，因为附件会成为无引用残留，而 Web workspace、归档、置顶与反馈 sidecar 仍会指向已删除 session。

**通过运行中的 profile 插件重置设置。** 不采用，因为配置损坏导致 profile 无法启动时仍必须能够重置，而且删除由启动器管理的 home 数据不需要应用树。

**只提供完整重置。** 不采用，因为模型设置与托管凭据独立于聊天历史，重新配置它们可能成本很高。

## 后果

用户可以清空全部对话而无需重新配置提供方，也可以有意将安装恢复为首次运行状态。启动器在已安装版本与源码 checkout 中提供相同行为。自定义部署若把其他聊天相关数据放在这三个标准子目录之外，仍需自行管理这些数据；放在 `$DSH_HOME` 内的任何数据都会被完整重置包含。

## 测试

CLI 参数测试固定 reset 分发，并拒绝混用父选项或额外参数。文件系统测试覆盖仅聊天保留配置、完整删除、否定确认、无效选择和宽泛 home 拒绝。源码命令冒烟证明 `pnpm dsh:reset` 会进入交互式启动器，且取消不会删除数据。
