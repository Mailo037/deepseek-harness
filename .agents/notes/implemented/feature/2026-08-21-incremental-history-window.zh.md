# Agent Note: 聊天会话只打开短窗口，向上滚动时按页加载历史

Status: implemented

[English](2026-08-21-incremental-history-window.md) | 中文

## 问题

打开长会话时，浏览器一次请求 `PAGE_MESSAGES`（50）条消息的尾页：长对话在读者看到任何内容之前就拉了一大块窗口，更早的历史只能通过明确的“加载更早”按钮到达。没有办法让会话打开在一个短的近期上下文上，并在读者向上滚动时分页加载其余部分。

## 决策

聊天会话现在打开在一个短的近期窗口上，在向上滚动时分页加载更早的历史。

运行时在 `Session.doOpen` 中的 tail 页大小变为 `INITIAL_PAGE_MESSAGES`（4 条消息：最后两个请求/响应对），而更早历史的页面保持 `PAGE_MESSAGES`（50）。`loadOlder` 和 gap repair 保持原有的页面大小——只有初始的 `session.history` 拉取被缩短了，因此长会话立即挂载一个小的近期窗口，而不是 50 条消息的 tail 页。

ChatView 在现有按钮（保留，使得短的可滚动窗口始终有操作入口）之外增加了两种到达更早历史的方式：

- **向上滚动分页**：读者滚动到已加载窗口的顶部（`el.scrollTop <= OLDER_TRIGGER_TOP`，8px），且满足 `hasMore && !loadingOlder && openState === 'open'` 时，通过现有的锚定 `loadOlder` 路径拉取下一页，并在 prepend 后保持阅读位置。`movedByReader` 保护防止程序化的 prepend 调整重新触发。
- **自动填充**：当已加载窗口未填满滚动容器（`clientHeight > 0` 且 `scrollHeight - clientHeight <= 0`）时，效果持续拉取页面直到流可滚动或历史结束，因此初始的 4 条消息窗口始终可以滚动。固定底部的读者保持固定（prepend 在之上增长，follow 逻辑处理）；`clientHeight` 保护使 jsdom 单元测试保持在滚动驱动的路径上。

## 备选方案

**保持打开时加载 50 条消息，仅依赖现有按钮。** 已拒绝：用户要求短的近期窗口加上向上滚动分页，而短窗口往往比视口短，仅靠向上滚动分页在窗口溢出前无法到达更早历史。

**通过更大的页面恰好加载两个用户请求后停止。** 已拒绝：`maxMessages` 计数包括用户和助手消息，且主机在消息组边界切分，因此“两个请求/响应对”自然就是 `INITIAL_PAGE_MESSAGES = 4`；更大的初始页面会使此更改意在消除的“打开时大窗口”行为重现。

**在较宽的范围内（160px）触发向上滚动分页。** 已拒绝：与那些将读者滚动到定位锚点（偏移量 50/80）作为锚点保持测试设置的单元测试冲突；缩小到顶部区域（8px）使这些阅读位置不会被误判为页请求，同时 e2e 中的 `wheelToHistoryStart` 和 `scrollTop = 0` 仍然触发。

## 后果

长对话快速打开到短的近期上下文上，向上滚动（或现有按钮）逐页加载其余部分。运行时和 UI 始终保留分页入口，因此即使初始窗口未填满视口，历史也不会被隐藏。由于初始的 `session.history` 拉取更小，stats/aria/perf 的 e2e 期望（“第一次打开时挂载了哪些轮次”）发生了变化；那些断言恰好 24 轮初始窗口的测试现在断言一个有界的部分窗口，而通过按钮驱动分页的测试现在通过滚动到加载窗口顶部来驱动分页。
