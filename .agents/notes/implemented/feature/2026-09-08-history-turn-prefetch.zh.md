# Agent Note: 折叠历史轮次与延迟前缀预取

Status: implemented

[English](2026-09-08-history-turn-prefetch.md) | 中文

## Problem

按消息分页的历史记录可能缺少已完成轮次的开头。等待用户逐页向上滚动后才显示耗时折叠行，会使会话在多次分页之后突然收起。

## Decision

历史响应携带部分工作位于页面之前的已完成轮次的日志时间和起始序号。浏览器在连续事件窗口之外保留这些元数据并立即显示耗时折叠行。每次成功分页后，经过可配置的阅读间隔再请求前缀，直到轮次开头进入窗口。展开操作立即请求下一页。补载保留分组标识及展开状态；读取失败后允许用户重试，不自动循环重试。

[日志顺序会话决策](../../implemented/bug-fix/2026-07-30-web-transcript-log-ordered-projection.zh.md) 继续规定事件顺序和压缩显示。时间元数据不会合成日志事件，也不会在组装器的事件窗口中引入空洞。

## Alternatives considered

**显示历史前加载全部事件** 会延迟首屏，而且成本随完整日志增长。

**稀疏摘要与独立详情区间** 需要另一套事件窗口表示及实时事件合并规则。连续前缀分页复用现有组装器和传输，同时把中间工作隐藏在最终分组中。

## Consequences

首个页面保持较小，隐藏工作无需反复滚动即可加载。由于仍按消息分页，前缀页可能包含更早的轮次。Host 仍读取会话快照来定位轮次起止。通过不完整页面出现的轮次在补载后保持折叠，即使少于通常的十个动作阈值。运行中的轮次保持流式显示。

Host、运行时及组件测试覆盖时间元数据、前缀完成、取消及展开状态连续性。无需密钥的浏览器场景播种六十个步骤，检查多页补载和折叠后的会话快照。

输入栏的文件变更摘要也允许收到的统计投影暂时缺少 `fileChanges`，在完整投影到达前使用已加载轮次中的变更。客户端存储不会按领域校验投影载荷，因此开发更新期间，运行中的 Host 与刷新的浏览器可能使输入栏崩溃。回归测试覆盖不完整投影到完整投影的转换。
