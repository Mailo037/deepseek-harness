# Agent Note: Evidence-oriented agent tools

Status: proposed

[English](2026-08-24-evidence-oriented-agent-tools.md) | 中文

## Problem

编程 agent 需要来自当前上下文窗口之外的证据：先前的 Session、源代码语法、测试失败、仓库历史、持久运行时状态和已渲染的浏览器状态。加载完整 JSONL transcript 会使这些证据昂贵、嘈杂、陈旧，并可能泄露密钥。纯文本搜索也无法区分源代码与注释或字符串，通用 shell 访问则无法向模型提供紧凑且可比较的诊断结果。

现有的 [`@deepseek-ai/dsh-tool-session-query`](../../../../packages/session-query/tool-session-query/README.zh.md) 已提供选择加入、经工作区授权的 Session 全文搜索和精确事件检查。它特意没有提供紧凑的 Session 概述、陈旧上下文事实、面向模型的历史内容脱敏、结构化代码搜索、项目记忆、标准化测试报告、Git 溯源、语言内核或浏览器 DOM 证据。每个缺失能力都迫使 agent 要么用通用工具重建过多数据，要么在缺少相关证据的情况下工作。

## Proposal

引入一组选择加入、以证据为导向的工具。每个工具返回带来源位置或持久事件引用的有界可读结果，其完整结果仍作为普通、已记录的 `tool/result`。工具不得仅因模型提供了一个标识符就读取整个 transcript、仓库历史、进程环境、浏览器配置文件或命令日志。设置负责部署相关的上限、超时、存储位置和允许的后端。

### Prior-Session retrieval

扩展 `@deepseek-ai/dsh-tool-session-query`；不引入 `read_whole_chat`。`session_search` 和 `session_event_search` 继续用于发现，`session_event_read`、`session_event_trace` 和 `session_trace` 继续用于精确的后续检查。新增 `session_summary(session_id)` 作为有界、事件支持的概述：已陈述目标、已记录决策、明确观察到的改动文件、未解决工作、Session 标题、最后事件时间，以及仅限已记录的修订信息。每个概述字段都引用支撑它的事件或报告；不可用的事实保持缺失而不是推断。

跨 Session 结果仍限制在调用方完全相同的工作区标识内。历史提取、全文索引、概述、片段、追踪和精确读取都在内容到达面向模型的结果前通过一个密钥脱敏策略。该策略保留明确的脱敏标记和结果溯源，使 agent 可以知道信息被隐去而不会得到其内容。每个结果标记来源 Session 和最后记录的事实，让调用方判断证据是否可能陈旧。

### Structural code search and rewrite planning

新增源代码分析能力，并以 `ast-grep` Service Provider 作为第一个后端。模型可以发起语法感知查询，报告语言、文件、范围、匹配节点种类和有界源代码摘录。结构化改写先返回普通 diff 提案；应用它使用现有的文件系统修改策略和版本保护。该能力绝不把注释或字符串中的匹配当作语法调用点。

### Project memory

新增工作区范围的项目记忆存储，用于并非 Session transcript 的持久运行知识：平台约束、项目约定、已验证命令，以及附带证据的决策。`project_memory_search` 返回有界的匹配条目，而 `project_memory_record` 仅在已挂载策略允许时写入经过验证的条目。条目带有证据引用、工作区范围、可用时的记录修订、作者、过期或重新验证规则以及敏感性分类。

项目记忆是独立存储，不是 `.agents/notes/`，并且绝不接收密钥、凭据、原始 transcript、浏览器 cookie 或无界工具输出。检索是显式并经排序的；未经审查的记忆不会在任务开始时无条件成为提示词文本。后续策略可以在使用证据表明它能提升任务成功率后，选择可信且新鲜的条目进行注入。

### Structured test and diagnostic reports

新增基于已配置命令配置文件的测试运行器消费方。它通过现有子进程和沙箱策略执行所选测试命令，识别受支持的运行器输出，并返回包含状态、耗时、失败测试名称、简短堆栈跟踪、断言 diff 和保留的脱敏输出定位符的标准化报告。运行器格式未知时，模型看不到捏造的通过或失败分类；它会获得命令结果和明确的不受支持格式诊断。

### Read-only Git intelligence

新增 Git 检查工具，以仓库相对位置和提交标识呈现目标 `blame`、文件历史、提交范围和改动模块查询。它只接受只读操作。暂存、提交、推送、变基和其他修改仍由其现有命令和权限路径负责。

### Stateful language kernels

当一次性代码执行或 PTY 不足够时，新增用于简短 Node.js 和 Python 实验的已配置语言内核提供方。`repl_eval`、`repl_inspect` 和 `repl_reset` 操作一个由 Agent 拥有、状态、进程生命周期、输出和资源用量均有上限的内核。内核共享选定的执行环境和沙箱策略，在其所有者 dispose 时 dispose，并且绝不成为由无关 Session 共享的进程级存储。

### Browser and DOM evidence

新增与 HTTP Web 搜索和抓取分离的浏览器能力。其初始提供方运行没有用户 cookie 的隔离 headless 配置文件。只读工具为允许的来源返回有界的可访问性/DOM 快照、截图、控制台错误和失败的网络请求。浏览器操作、认证配置文件、下载和任何外部修改都需要单独配置的支持以及现有权限策略。快照提取会在结果被记录或展示给模型前删除凭据、表单值、cookie、授权头和其他敏感浏览器状态。

## Delivery order

建议顺序以结果为导向，而不是已承诺的发布计划：

1. **Now — Session evidence and test diagnostics.** 向当前 Session 查询系列添加 `session_summary`、统一脱敏和新鲜度事实，然后使常规测试失败紧凑且可比较。
2. **Next — Structural code and Git evidence.** 新增基于 AST 的匹配和改写提案，随后新增只读溯源和改动模块检查。
3. **Later — Project memory, kernels, and browsers.** 这些功能需要保留、资源生命周期和隐私策略，应根据早期证据工具的观察到的使用情况设计。

本提案不移除或推迟现有已承诺项目。每个交付阶段在排期前都需要一份单独负责的实现提案。

## Alternatives considered

**公开原始 `read_whole_chat` 或 transcript 下载工具。** 拒绝，因为它会把上下文花在无关历史上，使陈旧陈述看起来像当前事实，并可能将密钥复制到新的 Session。搜索、概述、追踪和精确有界读取保留调查路径，而不会自动批量披露。

**对每个证据需求都使用纯 `grep` 和任意 shell 命令。** 拒绝，因为语法查询、跨 Session 授权、标准化测试诊断、Git 溯源和浏览器快照具有不同的数据模型和失败语义。通用工具仍是有用的后续手段，而不是主要证据接口。

**在每个任务开始时自动注入所有已记住的项目事实。** 拒绝，因为旧的或不可信的记忆会成为提示词噪声，并可能使工作偏向过时决策。检索必须保持有范围、有来源支持且有界。

**将 DOM 自动化折入现有 HTTP Web 能力。** 拒绝，因为浏览器拥有 cookie、页面状态、渲染时机和 HTTP 搜索及抓取不具备的外部操作风险。单独的能力使其隔离和权限规则保持可见。

## Acceptance criteria

- Session 发现、概述、追踪和精确读取保持有界、经工作区授权、标记来源，并在模型可见前脱敏；没有工具接受完整 transcript 请求。
- AST 后端区分语法节点与注释和字符串，返回稳定位置，并将每次改写发送到普通 diff 和文件系统策略。
- 项目记忆条目有工作区范围、证据支持、敏感性分类、可过期，并可独立搜索；自动提示词注入保持禁用，直到策略明确启用。
- 受支持的测试配置文件返回已解析的失败和一个脱敏的保留输出定位符；不受支持的输出绝不获得捏造分类。
- Git 检查是只读的，并为 blame、历史和改动范围操作返回确定性的提交和路径引用。
- 语言内核由 Agent 拥有、受沙箱保护、资源有界，并随其所有者 dispose；无关 Session 无法读取其状态。
- 浏览器快照使用隔离配置文件并脱敏敏感浏览器状态；除非后续提供方和权限策略启用，否则不存在操作和认证浏览。
- 每个面向模型的工具都具有静态 schema、已记录的渲染意图、聚焦的单元覆盖、无密钥的组装快照和配置验证。组合部署只挂载其配置文件启用的工具。

## Risks

- 脱敏策略可能遗漏一种凭据格式或删除有用的诊断上下文。在公开任何历史内容前，它必须针对有代表性的工具、transcript、Git、终端和浏览器数据进行集中测试。
- Session 概述和项目记忆可能陈旧。事件引用、最后记录的事实、可用时的修订元数据和过期规则使不确定性可见，但不能证明检出仍然匹配。
- AST 解析器和测试输出适配器可能不支持语言或运行器版本。工具必须报告不受支持状态，而不是回退到会误导的文本解析。
- 持久内核和浏览器比一次性命令保留更久的状态。生命周期上限、所有者范围的 dispose、沙箱和明确的配置文件选择以部分便利性为代价限制这些状态。
- 这是一组广泛的工具。交付顺序避免浏览器或记忆子系统成为基础 Session 和诊断改进的依赖。
